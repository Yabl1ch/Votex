## Фаза 1: Серверный монолит и инфраструктурный харднинг (Backend VPS)

### Цель этапа:
Создать полностью автономный, идемпотентный bash-скрипт `scripts/votex-install.sh`, выполняющий за один проход харднинг ОС, установку VPN-ядра, генерацию ключей, бенчмарк и запуск сервиса подписки.

### Задачи:
1. **Разработка скрипта `scripts/votex-install.sh`**:
   - Реализация pre-flight проверок (root-доступ, определение дистрибутива Ubuntu/Debian).
   - Применение системного тюнинга ядра `/etc/sysctl.d/99-votex.conf` (включение TCP BBR, fq, защита от SYN-flood).
   - Развертывание и конфигурация `fail2ban` (джейл sshd, макс. 4 попытки, бан на 24 часа).
   - Настройка `ufw` фаервола (закрытие всех портов кроме 22, 20443, 2053, 8443, 2083, 2088).
2. **Установка сетевого стека**:
   - Автоматическая установка последней версии `Xray-core` и `Hysteria 2`.
   - Автоматическая генерация пары ключей X25519 (`xray x25519`), `shortId`, клиентского `UUID` и секретного токена подписки.
3. **Развертывание мультипротокольной конфигурации All-in-One**:
   - Внедрение 5 inbounds (Reality Vision 20443, SplitHTTP 2053, gRPC 8443, Hysteria 2 2083, Shadowsocks 2088).
   - Маскировка под доверенные домены (SNI `addons.mozilla.org` / `dl.google.com`).
4. **Служба раздачи подписки**:
   - Развертывание микросервиса отдачи подписки по токену `GET /sub/{TOKEN}` (форматы Base64 и JSON с маршрутизацией РФ Direct и фрагментацией).
5. **Встроенный бенчмарк скорости**:
   - Замер пинга до Cloudflare/Google и тест пропускной способности через CDN.

### Критерии приемки и верификация:
- [ ] Скрипт проходит синтаксическую валидацию `bash -n scripts/votex-install.sh` (код возврата 0).
- [ ] Shellcheck не выдает критических ошибок (`SC2086`, `SC2154`).
- [ ] Сервер генерирует валидный JSON отчета `/var/log/votex-report.json`.

## Фаза 2: Инициализация ядра Tauri v2 и нативного SSH-модуля (Rust Core)

### Цель этапа:
Инициализировать проект Tauri v2 с бэкендом на Rust, реализовать безопасный модуль подключения по SSH и потоковую передачу терминального вывода в графический интерфейс.

### Задачи:
1. **Инициализация проекта Tauri v2**:
   - Настройка `src-tauri/Cargo.toml` с необходимыми крейтами: `tauri`, `russh` (или `ssh2`), `tokio`, `serde`, `serde_json`, `ring`, `reqwest`.
   - Конфигурация окна приложения (безрамочное стекло, кастомная панель заголовка, минимальный размер 960x640).
2. **Разработка SSH-провизионера (`src-tauri/src/commands/ssh.rs`)**:
   - Функция `run_provisioning(host, port, user, password)`: асинхронное подключение к VPS.
   - Заливка и выполнение `votex-install.sh`.
   - Потоковая отправка логов по строкам через Tauri Events (`emit("ssh-log", line)`).
   - Перехват финального JSON отчета сервера и сохранение в локальное состояние.
3. **Безопасное хранилище учетных данных (`src-tauri/src/vault.rs`)**:
   - Локальное шифрование учетных данных сервера (IP, порт, токен подписки) с помощью AES-GCM / Ring.
4. **Команды управления сервером**:
   - `test_vps_connection(host, port)`: быстрый TCP-пинг доступности порта 22.
   - `fetch_server_metrics(host)`: опрос статуса служб Xray, Hysteria и счетчика банов Fail2ban.
   - `reboot_vpn_services(host)`: перезапуск systemd-юнитов при необходимости.

### Критерии приемки и верификация:
- [ ] Команда `cargo check` в папке `src-tauri` завершается успешно без ошибок типов.
- [ ] Unit-тесты для парсера ответов бенчмарка и SSH-команд проходят (`cargo test`).

## Фаза 3: Фронтенд и дизайн-система `organic-glass-bento-ui` (React + TypeScript)

### Цель этапа:
Создать безупречный интерфейс приложения в фирменном стиле пользователя с матовым органическим стеклом, изумрудно-мятными акцентами, пружинными анимациями и чистыми SVG-иконками (без эмодзи).

### Задачи:
1. **Настройка окружения фронтенда**:
   - React 19, TypeScript, Tailwind CSS v4, Framer Motion, Zustand.
   - Подключение дизайн-токенов `organic-glass-bento-ui`:
     - Точечный фон Dot-Matrix (`background-size: 22px 22px`).
     - Матовое стекло: `backdrop-filter: blur(24px) saturate(160%)`.
     - Палитра: обсидиановый фон `#06100C`, изумрудный акцент `#22C55E`, мятный `#4ADE80`.
     - Световой блик на гранях: `inset 0 1px 1px 0 rgba(255, 255, 255, 0.12)`.
2. **Разработка базовых Bento-компонентов**:
   - `BentoCard`: парящий контейнер с радиусом скругления, мягкой тенью и стеклянным размытием.
   - `BentoGrid`: адаптивная сетка с отступами `16px–24px` и шагом `gap: 16px–20px`.
   - `GlassButton`: кнопка с пружинной физикой нажатия (spring `stiffness: 320, damping: 26`) и градиентным свечением.
   - `GlassInput`: инпут с мягкой зеленой подсветкой фокуса.
   - `TerminalView`: высокопроизводительное окно живого терминала с автоскроллом и подсветкой синтаксиса этапов.
3. **Библиотека SVG-иконок**:
   - Комплект оптимизированных инлайн SVG-иконок (Shield, Server, Activity, Terminal, Link, Copy, Check, Refresh, Zap, Lock, Eye, AlertCircle).

### Критерии приемки и верификация:
- [ ] В коде и интерфейсе полностью отсутствуют Unicode-эмодзи.
- [ ] `pnpm tsc --noEmit` не выдает ошибок типизации.
- [ ] Все интерактивные элементы имеют плавные переходы (`transition-all duration-200`).

## Фаза 4: Реализация вкладок и бизнес-логики приложения

### Цель этапа:
Связать все вкладки интерфейса с бэкендом Tauri и обеспечить плавный пользовательский сценарий от ввода пароля до получения подписки.

### Задачи:
1. **Вкладка «Мастер установки» (`ProvisioningPage.tsx`)**:
   - Форма ввода данных VPS с валидацией.
   - Запуск провизионинга по клику на главную кнопку.
   - Живое отображение лога терминала и индикатора прогресса (1–100%).
2. **Вкладка «Главная» (`DashboardPage.tsx`)**:
   - Карточка здоровья сервера (Online/Offline, Uptime, локация).
   - Парящий блок быстрой подписки с кнопкой «Копировать ссылку» в 1 клик.
   - Монитор текущей задержки (Ping) с автообновлением.
   - Сетка карточек активных протоколов.
3. **Вкладка «Отчёты и бенчмарки» (`ReportsPage.tsx`)**:
   - Визуализация результатов замера скорости: шкалы Download / Upload (Мбит/с).
   - Сравнительный график задержки (Latency) для 5 протоколов (Reality, SplitHTTP, gRPC, Hysteria 2, Shadowsocks).
   - Кнопка «Повторить тест скорости» в 1 клик.
4. **Вкладка «Подписка и маршрутизация» (`SubscriptionPage.tsx`)**:
   - Подробная карточка подписки с кнопкой перегенерации токена.
   - Интерактивный визуализатор правил Smart Routing:
     - Прямой доступ (Банки, Госуслуги, .ru).
     - Защищенный туннель (Gemini, Claude, YouTube, Discord).
     - Блокировка (Apple Relay, BitTorrent).
   - Индикатор TLS-фрагментации пакетов для обхода ТСПУ.
5. **Вкладка «Безопасность и сервер» (`SecurityPage.tsx`)**:
   - Мониторинг отраженных атак Fail2ban и таблица заблокированных ботов.
   - Статус портов фаервола UFW.
   - Кнопки мягкого перезапуска сервисов Xray и Hysteria 2.
6. **Вкладка «Настройки» (`SettingsPage.tsx`)**:
   - Кастомизация темы, проверка обновлений на GitHub, таймауты SSH.

### Критерии приемки и верификация:
- [ ] Переключение вкладок происходит мгновенно с плавной анимацией перехода (fade-in / slide).
- [ ] Ошибки SSH и сети обрабатываются с информативными уведомлениями (без глушения).

## Фаза 5: Тестирование, сквозная проверка и релизная сборка

### Цель этапа:
Провести комплексную верификацию работы Votex, проверить совместимость со сторонними клиентами (Happ, v2rayN, sing-box) и собрать оптимизированный `.exe` бинарник.

### Задачи:
1. **Тестирование развертывания на тестовом VPS**:
   - Запуск `votex-install.sh` на чистой Ubuntu 22.04 / 24.04.
   - Проверка активации BBR (`sysctl net.ipv4.tcp_congestion_control`).
   - Проверка правил UFW (`ufw status verbose`) и джейлов Fail2ban (`fail2ban-client status sshd`).
2. **Проверка импорта подписки в Happ и v2rayN**:
   - Проверка отдачи по ссылке `https://<ip>:18080/sub/<token>`.
   - Проверка, что российские сайты открываются напрямую без замедления.
   - Проверка доступности Gemini, Claude и YouTube.
   - Проверка работы узла автоматического выбора (Auto-Select).
3. **Релизная компиляция Windows бинарника**:
   - Сборка легковесного `.exe` через `cargo tauri build`.
   - Проверка потребления оперативной памяти (< 30 МБ в простое).
   - Создание релизного тега на GitHub с прикреплением спецификации и инструкций.

### Критерии приемки и верификация:
- [ ] Приложение запускается без сторонних зависимостей на чистой Windows 10/11.
- [ ] Успешное выполнение сквозного сценария: чистый VPS $\to$ ввод данных в GUI $\to$ автоматическая настройка $\to$ получение работающей подписки.
