## 1. Введение и концепция системы

### 1.1. Назначение проекта
**Votex** — это легковесный, кроссплатформенный десктопный менеджер и автоматизированный инструмент развертывания персональной антицензурной VPN-инфраструктуры на чистые виртуальные серверы (VPS) в «один клик».

Проект решает ключевую проблему современного пользователя в условиях жестких сетевых блокировок (РКН, ТСПУ, DPI):
1. **Отсутствие технических знаний:** Обычный пользователь не умеет администрировать Linux, генерировать ключи шифрования, настраивать Xray или писать правила маршрутизации.
2. **Уязвимость серверов:** Обычный VPS сразу после покупки подвергается непрерывному сканированию ботами и попыткам брутфорса SSH.
3. **Блокировка протоколов:** Классические протоколы (OpenVPN, WireGuard, обычный ShadowSocks) блокируются DPI-системами по сигнатурам.
4. **Неудобство повседневного использования:** Без раздельной маршрутизации перестают открываться российские банки (Сбер, Т-Банк), Госуслуги, маркетплейсы (Ozon, Wildberries), либо сам VPN блокируется российскими сервисами.

### 1.2. Роль Votex
Votex выступает **умным оркестратором и генератором подписки**:
- Пользователь вводит только IP и root-пароль купленного VPS.
- Приложение через встроенный нативный SSH-клиент накатывает монолитный скрипт автоматической настройки: выполняет харднинг сервера, настраивает фаервол UFW и защиту от ботов Fail2ban, включает TCP BBR, разворачивает мультипротокольный стек (VLESS Reality Vision, SplitHTTP, gRPC, Hysteria 2) с маскировкой под авторитетные зарубежные домены.
- Проводит автоматический бенчмарк скорости и пинга для всех узлов.
- Генерирует единую защищенную веб-ссылку на подписку с умной встроенной маршрутизацией (Smart Routing) и фрагментацией пакетов TLS (Client-side Fragmentation).
- Пользователь вставляет одну ссылку в удобный клиент (Happ, v2rayN, sing-box, Streisand) на телефоне или ПК и получает безупречно работающий интернет.

### 2.1. Клиентское приложение (Tauri v2 + Rust + React)
- **Ядро:** Rust 2021 Edition. Предоставляет максимальную производительность, микроскопическое потребление оперативной памяти (~15-25 МБ RAM против 300+ МБ у Electron), отсутствие внешних рантаймов и сборку в единый независимый бинарный `.exe` для Windows.
- **Интерфейс:** TypeScript 5.6+, React 19, Tailwind CSS v4, Framer Motion для физических пружинных микроанимаций.
- **Дизайн-система:** `organic-glass-bento-ui` (органичный глассморфизм, парящие бенто-модули, глубокая обсидианово-изумрудная гамма, точечный паттерн холста, векторные SVG-иконки, строгий запрет на эмодзи).

### 2.2. Серверная среда (VPS)
- **Поддерживаемые ОС:** Ubuntu 22.04 LTS, Ubuntu 24.04 LTS, Debian 11 Bullseye, Debian 12 Bookworm (архитектуры `x86_64` / `amd64` и `arm64`).
- **Сетевое ядро:** Xray-core (последний стабильный релиз v24.9+) и Hysteria 2.
- **Минимальные требования к VPS:** 1 vCPU, 512 МБ RAM (рекомендуется 1 ГБ), 10 ГБ NVMe/SSD, чистый IPv4 (поддержка IPv6 опциональна).

## 3. Серверная безопасность и Харднинг (Ironclad Defense)

Политика безопасности спроектирована с учетом потребностей обычного пользователя: **максимальная защита от ботов и взлома без риска заблокировать самого владельца сервера**.

### 3.1. Защита от брутфорса и сканеров (Fail2ban)
1. Устанавливается и запускается `fail2ban`.
2. Конфигурация джейла `sshd`:
   - `maxretry = 4` (после 4 неудачных попыток ввода пароля IP отправляется в бан).
   - `findtime = 600` (окно анализа — 10 минут).
   - `bantime = 86400` (первичный бан на 24 часа).
   - При повторных инцидентах срабатывает инкрементальный бан (бан до 7 суток).
3. Ведется локальный журнал заблокированных адресов, доступный для просмотра во вкладке «Безопасность» приложения Votex.

### 3.2. Межсетевой экран (UFW Firewall)
1. Политика по умолчанию: **`ufw default deny incoming`** (полный запрет любых входящих подключений) и **`ufw default allow outgoing`** (разрешены исходящие).
2. Белый список портов:
   - Порт `22/tcp` — стандартный SSH (сохраняется для гарантированного доступа без поломки подключения мобильных клиентов).
   - Порт `20443/tcp` — VLESS Reality Vision.
   - Порт `2053/tcp` — VLESS Reality SplitHTTP (xhttp).
   - Порт `8443/tcp` — VLESS Reality gRPC.
   - Порт `443/udp` — Hysteria 2 (UDP/QUIC, высокоскоростной протокол для гейминга и обхода цензуры).
   - Порт `443/tcp` — Hysteria 2 TCP Ping (Xray dokodemo-door: мгновенный SYN-ACK на клиентский TCP-пинг).
   - Порты `2083/udp` и `2083/tcp` — Legacy Hysteria 2 (iptables REDIRECT на 443/udp и dokodemo-door fallback).
   - Порт `2088/tcp` и `2088/udp` — Shadowsocks-2022.
   - Порт `18080/tcp` — Локальный порт сервиса подписки (проксируется или открывается с токенизированным путем).
3. Все остальные порты закрыты (режим Stealth). Сканеры портов типа Nmap получают `closed` / `filtered`.

### 3.3. Тюнинг ядра Linux (Kernel & TCP BBR)
В `/etc/sysctl.d/99-votex.conf` применяются оптимизации сетевого стека:
```ini
# Включение BBR congestion control для максимальной скорости и минимального пинга
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr

# Защита от SYN-Flood атак
net.ipv4.tcp_syncookies = 1
net.ipv4.tcp_max_syn_backlog = 8192
net.ipv4.tcp_synack_retries = 2

# Защита от IP Spoofing и Man-in-the-Middle
net.ipv4.conf.all.rp_filter = 1
net.ipv4.conf.default.rp_filter = 1
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.default.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.default.send_redirects = 0

# Увеличение буферов TCP для высокоскоростных соединений
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
net.ipv4.tcp_rmem = 4096 87380 16777216
net.ipv4.tcp_wmem = 4096 65536 16777216
net.ipv4.tcp_mtu_probing = 1
```

### 3.4. Автоматические обновления безопасности (Unattended Upgrades)
Активируется служба `unattended-upgrades`, устанавливающая критические патчи безопасности ядра и пакетов Debian/Ubuntu без перезагрузки системы.

## 4. Протокольный стек VPN и защита от ТСПУ/РКН

### 4.1. Мультипротокольный набор All-In-One
В конфигурации разворачиваются 5 параллельных независимых протоколов:

| Протокол | Транспорт | Порт | Маскировка (SNI) | Назначение |
|---|---|---|---|---|
| **VLESS Reality Vision** | TCP + XTLS | 20443 | `addons.mozilla.org` | Основной высокоскоростной протокол с нулевым оверхедом и прямым шифрованием |
| **VLESS Reality SplitHTTP (xhttp)** | HTTP/2-3 Chunks | 2053 | `addons.mozilla.org` | Ультимативный обход блокировок ТСПУ: разбиение трафика на псевдо-POST потоки со случайным паддингом |
| **VLESS Reality gRPC** | HTTP/2 gRPC | 8443 | `addons.mozilla.org` | Альтернативный мультиплексированный канал при шейпинге TCP |
| **Hysteria 2** | UDP / QUIC (+ TCP Ping) | 443 (Legacy 2083) | TLS (Self-signed + pinSHA256) | Низкий пинг для онлайн-игр, звонков Telegram/Discord, обход блокировок произвольных UDP-портов ТСПУ (порт UDP 443) |
| **Shadowsocks-2022** | TCP/UDP | 2088 | `blake3-aes-128-gcm` | Проверенный резервный протокол |

### 4.2. Профиль умной маршрутизации трафика (Smart Routing)
Для клиентов с поддержкой правил маршрутизации доступен JSON-профиль:
- **Название профиля:** `Votex`
- **Маршрутизация:** Встроенный роутинг разделяет потоки на клиенте без необходимости ручной настройки списков.
- Трафик к российским банкам и государственным сервисам идет напрямую (DIRECT), заблокированные сервисы и ИИ направляются через скоростной туннель (PROXY), а рекламные трекеры сбрасываются (BLOCK).

### 4.4. Архитектура Hysteria 2 Dual-Stack (UDP 443 + TCP Ping) и TLS Pinning
Провайдеры и ТСПУ в РФ массово глушат или замедляют произвольные UDP-порты (8443, 2083). Единственный порт, на котором UDP/QUIC не подвергается блокировкам — это **UDP 443** (легитимный трафик HTTP/3 / QUIC).

Для обеспечения 100% совместимости с клиентскими приложениями (Happ на iOS/Android/Windows, v2rayN, sing-box, Nekoray) реализована двухстековая архитектура:
1. **Сетевая изоляция стеков Linux:** В сетевом стеке ядра Linux протоколы TCP и UDP полностью независимы.
   - **`0.0.0.0:443/udp`:** Слушает демон Hysteria 2 (`listen: :443`), обрабатывая весь реальный высокоскоростной туннельный трафик.
   - **`0.0.0.0:443/tcp`:** Слушает входящий инбаунд Xray-core `dokodemo-door`, перенаправляющий запросы на локальный порт `127.0.0.1:18080`.
2. **Механика клиентского пинга (TCP SYN):**
   - Клиентские приложения при проверке задержки списка серверов выполняют быстрый **TCP Ping** (отправка SYN-пакета на хост и порт из URI).
   - Поскольку Hysteria 2 работает строго по UDP, отсутствие слушателя TCP на порту 443 приводило к отбрасыванию пакетов фаерволом и полному таймауту узла на всех платформах.
   - Xray `dokodemo-door` на TCP 443 мгновенно отвечает клиенту SYN-ACK, обеспечивая зелёную задержку (< 30 мс) во всех клиентах.
3. **Безопасность TLS и Self-Signed Сертификаты:**
   - Для Hysteria 2 генерируется самоподписанный TLS-сертификат (с расширением `subjectAltName=DNS:${REALITY_SNI},IP:${SERVER_IP}`) и надежным RSA-fallback.
   - В ссылку подписки передается хэш отпечатка: `&pinSHA256=${HY_CERT_SHA256}` в связке с `insecure=1&allowInsecure=1`. Это позволяет клиентам sing-box и Happ выполнять строгий certificate pinning без системных предупреждений о недоверенном CA.
   - Файлам сертификатов назначаются корректные права чтения (`chmod 644 /etc/hysteria/server.crt` и `server.key`).
4. **Межсетевой экран:** В UFW открыты оба протокола: `ufw allow 443/udp` и `ufw allow 443/tcp`.

### 4.3. Фрагментация пакетов TLS (Client Fragmentation)
Для подавления DPI-сигнатур ТСПУ (которые анализируют длину пакета ClientHello при рукопожатии TLS) в подписку внедряются директивы фрагментации:
- `packets: "1-3"`
- `length: "100-200"`
- `interval: "10-20ms"`
Пакет рукопожатия дробится на нетипичные мелкие фрагменты со случайным интервалом, из-за чего сенсоры DPI не могут извлечь SNI заблокированного домена и пропускают трафик.

## 5. Умная маршрутизация трафика (Smart Routing)

Маршрутизация зашивается прямо в структуру профиля подписки и конфига. Пользователю не требуется настраивать списки вручную.

```
                  ПОЛЬЗОВАТЕЛЬСКИЙ ЗАПРОС
                             │
                             ▼
              [ DNS Проверка и Анализ Домена ]
                             │
         ┌───────────────────┼───────────────────┐
         │                   │                   │
         ▼                   ▼                   ▼
    Российский сегмент   Заблокированные / ИИ   Реклама и Мусор
  (.ru, .su, Банки, Госуслуги) (YouTube, Discord, Gemini) (Apple Relay, Ads, Torrents)
         │                   │                   │
         ▼                   ▼                   ▼
    [ DIRECT ]          [ PROXY ]           [ BLOCK ]
  Напрямую без VPN    Через VPS туннель   Мгновенный сброс
  (Макс. скорость,    (Разблокировка,     (Экономия трафика,
   нет банов банков)   шифрование)         защита от абуз)
```

### 5.1. Правила категории DIRECT (Прямой доступ без VPN)
Трафик направляется через локального провайдера пользователя:
- Доменные зоны: `.ru`, `.su`, `.xn--p1ai`.
- Российские цифровые экосистемы: Yandex (`yandex.*`, `ya.ru`, `kinopoisk.*`), VK (`vk.com`, `vkvideo.ru`, `mail.ru`, `ok.ru`).
- Банки и финтех: Сбербанк (`sberbank.ru`, `sber.ru`), Т-Банк / Тинькофф (`tbank.ru`, `tinkoff.ru`), Альфа-Банк, ВТБ, Система Быстрых Платежей (СБП), МИР.
- Государственные сервисы: Госуслуги (`gosuslugi.ru`), ФНС (`nalog.gov.ru`), Мос.ру.
- Маркетплейсы и ритейл: Ozon, Wildberries, Авито, Яндекс Маркет, DNS, Мегамаркет.
- Потоковое видео РФ: RuTube, VK Видео, Кинопоиск, Иви, Okko.
- IP-диапазоны: `geoip:ru` и частные подсети `geoip:private`.

### 5.2. Правила категории PROXY (Через защищенный туннель Votex)
- Искусственный интеллект и нейросети:
  - Google Gemini: `gemini.google.com`, `generativelanguage.googleapis.com`, `ai.google.dev`.
  - Anthropic Claude: `claude.ai`, `anthropic.com`.
  - OpenAI ChatGPT: `chatgpt.com`, `openai.com`, `oaistatic.com`.
  - Midjourney, Perplexity, Copilot.
- Заблокированные социальные сети и медиа: YouTube, Instagram, Facebook, X (Twitter), LinkedIn.
- Мессенджеры и коммуникации: Discord (`discord.com`, `discord.gg`, `discordapp.com`), голосовые каналы Telegram.
- Образовательные и IT-ресурсы: GitHub, Docker Hub, Medium, зарубежные документации.
- Все остальные зарубежные домены и IP-адреса по умолчанию (`outboundTag: proxy`).

### 5.3. Правила категории BLOCK (Черный список)
- Apple Private Relay (`mask.icloud.com`, `dns.apple.com`) — предотвращает утечки DNS мимо системных правил.
- BitTorrent протокол (`protocol: bittorrent`) — блокируется для защиты VPS от жалоб правообладателей (DMCA) и отключения сервера хостингом.
- Известные рекламные трекеры и фишинговые домены (`geosite:category-ads-all`).

## 6. Сервис защищенной подписки (Stealth Subscription Micro-Service)

На стороне сервера скрипт `votex-install.sh` разворачивает изолированный легковесный микросервис (или защищенный endpoint):
- **Слушает:** порт `18080` (привязан к локальному интерфейсу или проксируется через защищенный порт).
- **Секретный путь:** `/sub/{SUBSCRIPTION_TOKEN}`, где токен — случайно сгенерированная криптографическая строка (32 байта Hex).
- **Форматы ответа:**
  - При запросе с заголовком Happ/v2rayN/sing-box или параметром `?format=json`: возвращает полноценный валидированный JSON-профиль со всеми inbounds, outbounds, DNS-серверами, правилами smart-routing и фрагментацией.
  - При стандартном HTTP GET запросе: возвращает Base64-подписку с мета-заголовками:
    - `Subscription-Userinfo: upload=0; download=0; total=1073741824000; expire=0`
    - `Profile-Title: Votex`
    - `Profile-Update-Interval: 24`
    - `Profile-Test-Url: http://cp.cloudflare.com/generate_204`
    - `Profile-Web-Page-Url: https://github.com/Yabl1ch/Votex`

## 7. Монолитный bash-скрипт развертывания (`votex-install.sh`)

Скрипт представляет собой автономный, идемпотентный bash-файл со строгим контролем ошибок (`set -euo pipefail`).

### 7.1. Этапы выполнения скрипта
1. **Предварительная валидация (Pre-flight Checks):**
   - Проверка прав суперпользователя (`EUID == 0`).
   - Определение дистрибутива (Ubuntu 20/22/24, Debian 11/12).
   - Проверка наличия свободного места и памяти.
2. **Харднинг операционной системы:**
   - Обновление репозиториев: `apt-get update && apt-get upgrade -y`.
   - Установка необходимых утилит: `curl`, `wget`, `jq`, `ufw`, `fail2ban`, `openssl`, `uuid-runtime`, `tar`, `systemd`.
   - Применение сетевого тюнинга `/etc/sysctl.d/99-votex.conf` (TCP BBR + буферы).
   - Настройка `fail2ban` джейла `sshd` с лимитом 4 попытки.
   - Настройка фаервола `ufw`: блокировка всего, открытие портов 22, 20443, 2053, 8443, 2083, 2088.
3. **Установка ядра Xray-core и Hysteria 2:**
   - Загрузка официальных проверенных релизов Xray-core и Hysteria 2.
   - Генерация ключей X25519 для Reality:
     - `xray x25519` -> `PRIVATE_KEY` и `PUBLIC_KEY`.
     - Генерация `SHORT_ID` (16 знаков hex).
     - Генерация уникального клиентского `UUID` (`uuidgen`).
     - Генерация пароля для Shadowsocks-2022.
4. **Формирование серверной конфигурации:**
   - Создание `/usr/local/etc/xray/config.json` с 5 inbounds и маскировкой SNI под `addons.mozilla.org`.
   - Создание конфигурации Hysteria 2 `/etc/hysteria/config.yaml`.
   - Создание systemd-юнитов с автозапуском `systemctl enable --now xray hysteria-server`.
5. **Запуск бенчмарка скорости и доступности:**
   - Измерение времени рукопожатия (handshake latency) до Cloudflare / Google DNS через каждый порт.
   - Тест пропускной способности канала (скачивание 25 МБ тестового файла через CDN).
   - Сохранение результатов в `/var/log/votex-benchmark.json`.
6. **Запуск сервиса подписки и финальный вывод:**
   - Запуск `votex-sub-service`.
   - Формирование итогового отчета в формате JSON, передаваемого в Tauri через SSH.

### 8.2. Механизм потокового SSH (Rust `russh` / `ssh2`)
При нажатии кнопки «Начать автоматическую настройку»:
1. Rust бэкенд открывает SSH сессию к IP на порту 22 с переданным паролем или ключом.
2. Подписывается на каналы `stdout` и `stderr`.
3. Каждая строчка лога в реальном времени через событие `app_handle.emit("ssh-log", chunk)` пробрасывается во фронтенд.
4. Встроенный эмулятор терминала с плавной прокруткой отображает текущий шаг (например: «[3/7] Установка Xray-core...», «[5/7] Запуск бенчмарка...»).
5. По завершении скрипта сервер возвращает финальный JSON-пакет конфигурации с токеном подписки.

- **Bento-модули:**

## 10. Оценка полезности и стратегических преимуществ Votex

| Критерий | Votex | Amnezia VPN | Outline VPN | Панели (3X-UI / Marzban) |
|---|---|---|---|---|
| **Порог входа для новичка** | **Нулевой (1 клик)** | Средний (нужен выбор протоколов) | Низкий | Высокий (нужна ручная настройка веба и портов) |
| **Устойчивость к ТСПУ/РКН** | **Максимальная** (Reality Vision + SplitHTTP xhttp + фрагментация) | Высокая (AmneziaWG / Xray) | Низкая (Shadowsocks массово блокируется) | Зависит от квалификации администратора |
| **Умная маршрутизация РФ** | **Встроена «из коробки»** (Банки и Госуслуги работают нативно) | Требует ручной правки списков | Отсутствует | Требует ручной настройки клиентских JSON |
| **Раздельная маршрутизация** | **Да (Smart Routing)** | Нет | Нет | Нет |
| **Безопасность VPS** | **Встроенный харднинг** (Fail2ban, UFW, тюнинг ядра) | Базовая | Базовая | Отсутствует (панели часто ломают боты) |
| **Использование ресурсов** | **~20 МБ RAM (Tauri)** | ~250 МБ (Qt/Electron) | ~180 МБ (Electron) | Веб-браузер |
| **Совместимость с клиентами** | **Happ, v2rayN, sing-box** | Только клиент Amnezia | Только клиент Outline | Любые |

### Ключевая ценность:
1. **Независимость:** Пользователь владеет собственным сервером за 1.5–3$ в месяц и не зависит от публичных VPN-сервисов, которые блокируются целыми пулами IP.
2. **Неуязвимость для DPI:** Сочетание Reality + SplitHTTP гарантирует работу даже при белых списках и жестком глушении протоколов.
3. **Бесшовность жизни:** Работают одновременно и YouTube в 4K, и оплата в приложении Сбербанка/Т-Банка без необходимости каждый раз включать и выключать VPN.
